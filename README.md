Merge combines two branches while keeping both of their history.

Rebase avoids unnecessary merge commits and helps keep history linear. This is done by
     moving the commits into another branch.

Squah combines different commits into a single commit.

Cherry-pick copies a specific commit from one branch to another.

Nothing memorable comes to mind when recalling the git histoy for each feature. 


The Cherry-pick strategy would be used when fast action is required. This could be a software 
     bug that ends the program. 

The Rebase strategry can be used when a developer is assigned to work on two different features.
     The developer finishing work on the first feature and begins work on the second. To ensure
     consistancy in the finished assignments they would use rebase to add the commits to both
     branches.

The Merge strategy would be used to test the functionality of a single feature. This would ensure 
     that the updated code does not break the program.
